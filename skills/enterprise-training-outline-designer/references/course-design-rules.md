# 课程设计规则

## 从成果倒推

以“培训后，学员能够……”开头定义总成果。模块、案例、练习和时间都必须服务该成果；若某项不服务成果，应删除或放入课后扩展。

## 难度与方式

| 条件 | 设计选择 |
|---|---|
| 学员为小白 | 场景化语言、统一案例、示范和可直接套用的模板；避免先讲完整理论体系。 |
| 学员已有经验 | 用诊断、案例拆解、共创和真实业务迁移替代重复工具教学。 |
| 线上 | 每段讲授尽量短；用统一案例和明确操作任务维持节奏；预留互动检查点。 |
| 线下 | 安排分组研讨、个人迁移、现场辅导和成果展示。 |
| 半天 | 一个核心成果、两至三个模块；必须说明被延后或删去的内容。 |
| 一天 | 三至五个模块；形成“理解—示范—练习—迁移—复盘”的闭环。 |
| 多天 | 第一天建立共同语言和基础，后续逐步增加业务应用、共创和复盘。 |

## 时间校验

把所有教学、练习、展示、答疑和休息写入日程。总时长必须与客户约定相符。没有明确作息时，先说明默认假设，不要伪造精确时间。

## 模块质量标准

每个模块至少有一个明确产出，例如：行动清单、场景诊断、案例方案、沟通脚本、流程草图、业务应用计划或复盘表。避免把“理解概念”作为唯一产出。
