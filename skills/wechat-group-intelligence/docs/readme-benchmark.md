# README benchmark for a single Agent Skill repository

Research date: 2026-09-09

## Primary repositories reviewed

### Anthropic Skills

The [Anthropic Skills repository](https://github.com/anthropics/skills) opens with the Skill concept and repository purpose, then presents platform-specific usage, a basic Skill anatomy, a disclaimer, and related resources. Its useful pattern is to establish the standard and operating boundary before implementation details.

### Vercel Agent Skills

The [Vercel Agent Skills repository](https://github.com/vercel-labs/agent-skills) presents the available capabilities first, followed by a short installation command, usage examples, discovery information, Skill structure, and license. Its useful pattern is fast time-to-first-use and a scannable capability map.

### Superpowers

The [Superpowers repository](https://github.com/obra/superpowers) uses a table of contents, a “how it works” explanation, platform-specific installation, the basic workflow, library contents, philosophy, community, contribution, update, and license sections. Its useful pattern is a clear path from product promise to operating model and maintenance.

### Skills for Real Engineers

The [Skills for Real Engineers repository](https://github.com/mattpocock/skills) uses a visual hero, an ecosystem badge, a fast installation section with collapsible variants, and a problem-driven explanation of why the Skills exist. Its useful pattern is an immediate identity followed by concrete user pain and a low-friction start.

## Structure selected for this repository

This is a single Skill, not a large collection. The README should therefore use:

1. Product identity, status badges, and one-sentence value.
2. Short in-page navigation.
3. A 30-second installation and first invocation.
4. A comparison showing why this is not an ordinary chat summarizer.
5. One workflow diagram.
6. Capability and scene matrices.
7. A realistic evidence-shaped output example.
8. Input/output modes and repository architecture.
9. Evidence, privacy, authorization, and current-version boundaries.
10. Validation status, roadmap, contribution route, and license status.

Avoid unsupported adoption badges, fake CI status, excessive marketing copy, and installation commands that have not been grounded in the Agent Skills ecosystem.
