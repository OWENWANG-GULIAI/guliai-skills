# 公众号全流程交接契约

本文件定义总控 Skill 向写作、排版和草稿发布三个环节交付什么，避免“文案完成”被误报成“已经能发”。

## 输入与预期输出

| 输入 | 写作路由 | 图片规则 | 可发布条件 |
| --- | --- | --- | --- |
| 只有主题、观点或口述 | 观念/方法论类 | 生成 1 张独立横版封面与 3–5 张正文知识卡 | 图片逐张解释正文节点，封面为 2.35:1 且裁切可用 |
| 文档、课堂讲义、录音整理 | 根据主要用途判为方法论或教程 | 方法论生成知识卡；教程不生成操作图 | 教程中的所有操作点已有真实截图 |
| 学员材料、作品、反馈、聊天截图 | 学员案例类 | 只用明确授权的真实素材 | 必需事实与图片来源清楚，封面来自真实素材 |
| 初稿或待修改文章 | 保留可核验事实，重组表达 | 按最终文章类型路由 | 满足同一类型的图片和封面条件 |

## 三段交接

### 1. 写作与图文

`guyanyan-wechat-writer` 交付正文 Markdown、类型判定及理由、每张图片的路径与理解任务、封面候选，以及不能作为公开事实使用的内容。

知识卡不是装饰。1500–2500 字的观念文章通常用 3–5 个信息节点：核心分辨、任务/问题拆分、结构公式、路径流程、行动清单。它们可以有纸张拼贴、水彩纹理、手绘线条与清新低饱和配色，但必须在手机上读清信息；人物只在能帮助解释时出现，位置、动作、眼神和手势要对应结构方向。

封面不是首张正文卡。公众号头条封面按 2.35:1 制作，推荐 900×383 px 或 1080×460 px。关键标题、主体和品牌识别都应放在中心安全区，避免不同裁切中丢失。

### 2. 素材闸门

| 情况 | 允许继续？ | 处理 |
| --- | --- | --- |
| 方法论卡片未生成、失焦、文字不可读或只是氛围图 | 否 | 先重做相应知识卡 |
| 教程只写了“这里放截图”，没有真实截图 | 否 | 给出逐步骤截图清单，等待素材 |
| 案例缺少必须的照片/截图/作品或公开授权不明 | 否 | 指出需要哪份素材与授权范围 |
| 封面缺失、误用竖版正文卡或核心信息落在裁切边缘 | 否 | 方法论重做横版封面；教程/案例从真实素材中指定或裁切 |
| 用户明确要求仅交付文稿 | 是 | 到 Markdown 为止，不走排版和发布 |

### 3. 排版与草稿

`gzh-design` 读取 Markdown 与有效图片后，生成纯净 HTML 并通过其校验器。`baoyu-post-to-wechat` 只接收已验证的最终 HTML，负责上传封面和内文图片，并以 API 保存到草稿箱。使用者自行配置凭据，Skill 不需要也不得展示凭据。

## 草稿幂等与恢复

草稿 API 是“新建草稿”，不是“覆盖原草稿”。每次调用前，使用 `scripts/draft_state.py` 对最终 HTML 与所有上传图片取内容指纹。

- 同一指纹已有成功 `media_id`：跳过 API，不创建重复草稿；
- HTML、封面或任一正文图片变化：允许创建一份新草稿；
- 网络或 API 失败：不写成功状态；修改后可以安全重试；
- 不自动删除旧草稿，由用户在公众号后台决定取舍。

状态文件只保存路径、内容哈希、时间与草稿 `media_id`，不保存 AppID、AppSecret、Access Token 或文章正文。
