# 公众号全流程发布

把一篇文章可靠地交付到公众号**草稿箱**：先写清内容与图文，再排版，再通过已配置的公众号 API 建立草稿。这个 Skill 是总控，不替代子 Skill 的专业判断。

```text
输入主题 / 资料 / 已确认素材
        ↓
guyanyan-wechat-writer：写作、文章类型与图片路由
        ↓
素材闸门：检查真实素材、知识卡、封面和事实边界
        ↓
gzh-design：生成并校验可发布 HTML、预览
        ↓
baoyu-post-to-wechat：上传图片并写入公众号草稿箱
        ↓
记录草稿指纹：同一成品不重复创建草稿
```

## 什么时候启动

以下说法默认启动全流程：

- “给我写一篇公众号文章”
- “把这份资料整理成公众号文章”
- “写完直接排版并放到草稿箱”
- 只给主题、资料或口述内容，但明确要求沿用这套公众号工作流

若用户明确说“只写文案”“不要发布”“只要排版”，只完成其指定阶段。

草稿箱是本 Skill 的终点。**绝不自动群发、发布、定时发送或删除既有草稿。**

## 开始前：读取与定稿路径

1. 先调用 `guyanyan-wechat-writer`，由它读取用户本次提供或已确认可访问的写作资料，判定文章类型，并交付正文与图文清单。
2. 按 [全流程交接契约](references/pipeline-contract.md) 做素材、事实、封面与发布条件检查。没有安全且真实的输入时，明确说明缺什么；不要用生成图或占位符假装完成。
3. 按文章类型分路：
   - **观念/方法论类**：调用 `guliai-visual-design` 与图像生成能力，制作一张独立的公众号横版封面和 3–5 张有信息密度的正文知识卡。每张正文图要对应一个正文论点，封面按 2.35:1 规范设计，不能拿竖版正文卡充当。
   - **AI 教程实操类**：不生成操作示意图。正文有清晰的“第一步、第二步、第三步”，每个需要截图的位置写明具体截图内容；只有用户已提供、或在本次工作中能取得的真实截图齐全，才继续发布。
   - **学员案例类**：不生成 AI 配图。只使用用户提供、且确认可公开的学员照片、作品、截图或反馈；缺少必须的案例素材或封面时停在素材闸门。
4. 统一在一个明确的交付目录保存：原始 Markdown、图片、排版 HTML、预览和草稿状态文件。不要把凭据写入文章、HTML、图片元数据或工作报告。

## 可选固定尾图

若用户在本机提供且明确授权公开的个人介绍尾图，可在结论、行动邀请和必要文字尾签之后作为**最后一个内容块**插入。其后不再生成通用的 `END`、作者卡或第二段 CTA。没有该资产时，不创建占位图，也不影响其他文章流程。

## 素材闸门

发布前逐项确认：

- 标题、正文、署名与事实边界已经确认；
- 方法论类每张知识卡都能解释一个观点，封面是独立横版文件，符合 2.35:1，核心信息位于中心安全区；
- 教程的每个截图提示都有相应真实截图；案例的必要证据图都来自已确认素材；
- HTML 内所有图片都是有效本地文件或可上传文件，不含 `file://`、失效链接或读者可见的“此处放图”占位文字；
- 教程/案例的封面来自真实素材裁切或用户明确指定，不能临时生成一张假封面；
- 可选尾图仅在已确认的公开授权范围内使用，且是最后一个内容块。

不通过时，保存已完成的文稿与清单，准确说明所缺素材；不进行排版发布，也不创建半成品草稿。

## 排版与发布

1. 调用 `gzh-design`，用户指定主题时严格使用；未指定时根据文章阅读需求选择干净、留白充足的主题。保留正文图片的插入顺序与说明语义。
2. 用其校验器验证最终 HTML：`ERROR` 和 `WARNING` 都必须为 0；同时生成本地预览并检查标题层级、移动端留白、图片顺序和图片加载。
3. 选定封面后先检查草稿状态：

   ```bash
   python3 scripts/draft_state.py check \
     --state <交付目录>/.wechat-draft-state.json \
     --article <最终HTML> \
     --asset <封面> --asset <每张正文图>
   ```

   若返回 `already_published`，不要再次创建草稿；正文或图片变化时才允许新建。
4. 调用 `baoyu-post-to-wechat` 的 API 路径，使用已配置的凭据与白名单，将最终 HTML、封面、标题、摘要与署名上传为草稿。不得在输出、日志或文件中回显 AppSecret。
5. API 成功后记录草稿状态：

   ```bash
   python3 scripts/draft_state.py record \
     --state <交付目录>/.wechat-draft-state.json \
     --article <最终HTML> \
     --asset <封面> --asset <每张正文图> \
     --media-id <草稿media_id>
   ```

## 完成汇报

用用户能核对的结果结束：文章标题、类型、图片数量与用途、HTML/预览路径、是否已写入草稿箱、草稿 `media_id`。未发布时，准确说明卡在哪个素材或校验条件。
