# PRD 内容规范

## 编写原则

PRD 是开发依据，不是愿望清单。每项需求必须能追溯到用户问题或业务结果，并能通过可观察行为验收。用确定语言写已确认内容；假设、建议和待决定事项各自成区，不混进事实。

## 三种深度

- 轻量型：产品摘要、单一场景、输入、处理、输出、边界、测试和交付。
- 标准型：增加用户画像、能力拆分、追问与判断、异常处理、依赖和非目标。
- 高级型：再增加状态模型、工具权限、知识证据、隐私、降级、人工复核和分阶段范围。

不适用的模块省略，或用一句话说明“不需要及原因”。不要为了显得完整而虚构工具、记忆、知识库、长期跟进或多个输出版本。

## 需求写法

每项核心能力至少包含：

```text
用户问题：为什么需要这项能力
触发条件：什么输入或状态下启动
处理行为：Skill 必须完成的判断与动作
输出结果：用户可以看到或使用的结果
异常处理：信息缺失、矛盾或失败时怎么办
验收标准：什么观察结果代表通过
```

## 需求核对卡

PRD 草案前展示：

1. 一句话定位与核心用户结果。
2. 已确认事实。
3. 已标注假设及其影响。
4. 待决定事项、选项和推荐。
5. 本期范围与暂不开发。
6. 推荐复杂度、核心流程和主要风险。

影响目标、主要交付物或外部权限的待决定事项必须解决；其他事项可以保留在 PRD 中，不阻塞草案。

## PRD 自检

- 核心场景从触发到交付形成闭环。
- 输入缺失、冲突、不可读时有明确处理。
- 输出结构与实际使用者相匹配。
- 每项能力有可观察的验收行为。
- 本期范围与未来方向没有混写。
- 事实、假设、建议和未知可区分。
- 工具、数据、记忆和权限只在需要时出现。
- 测试包含正常、模糊、缺失、矛盾和边界情况。
- 没有未解释的占位内容或互相矛盾的要求。

## 模板选择

按复杂度分别使用 [轻量型模板](../assets/prd-templates/lightweight-prd.md)、[标准型模板](../assets/prd-templates/standard-prd.md) 或 [高级型模板](../assets/prd-templates/advanced-prd.md)。模板是输出骨架；生成最终 PRD 时替换所有方括号说明。
