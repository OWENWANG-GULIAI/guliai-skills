# 复杂度与路线判断

## 六维评估

每个维度记 0-2 分。评分用于选择合适的设计深度，不用于制造虚假的精确度。

| 维度 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| 任务 | 单一转换 | 一个主任务带辅助步骤 | 多场景或多个交付物 |
| 输入 | 稳定且结构固定 | 有缺失或多种常见格式 | 非结构化、多来源或持续补充 |
| 判断 | 无分支 | 少量可描述分支 | 多阶段、多规则或需专业判断 |
| 工具 | 不调用 | 只读或低风险工具 | 写入、发送、删除、发布等外部操作 |
| 知识 | 无专用资料 | 一套模板或有限资料 | 知识库、证据引用或多来源融合 |
| 状态与风险 | 一轮、低风险 | 需要会话上下文或人工复核 | 长期状态、敏感数据或高风险决策 |

## 路线

- **轻量型（0-3）**：使用轻量 PRD。固定任务、固定输出，不设计无依据的工具和记忆。
- **标准型（4-7）**：使用标准 PRD。明确追问、判断分支、异常处理和多种测试。
- **高级型（8-12）**：使用高级 PRD。设计状态、依赖、权限、风险、降级和验证链路。

无论总分多少，只要包含高风险专业决策、敏感数据处理或有后果的外部写入，就至少按高级型处理权限与风险部分。处于边界时，选择能覆盖真实风险的较高一级，但不要把未来设想计入当前复杂度。

## 路由输出

向用户显示：

```text
推荐类型：[轻量型 / 标准型 / 高级型]
主要依据：[影响最大的 2-3 个维度]
这意味着：[需要的 PRD 深度和验证方式]
不意味着：[不会因此自动增加的功能]
```

用户可以选择更轻的第一版。此时应缩小场景和能力，让留下的范围仍能形成闭环，而不是删除必要的安全和验收要求。
